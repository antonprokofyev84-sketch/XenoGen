## 1. Разделение ресурсов усталости (Stamina vs Expedition Points)

**Проблема:**
Использование индивидуальной стамины каждого персонажа для перемещения по глобальной карте создаёт микроменеджмент и проблему «слабого звена» (когда один уставший спутник блокирует движение всей группы). Использование общего пула в виде простого среднего арифметического математически наказывает игрока за добавление в отряд слабых сюжетных NPC.

**Решение: Семантическое разделение ресурсов**
Вводится два независимых ресурса, чтобы отделить макроэкономику (выживание отряда в пустоши) от микроэкономики (личные действия игрока в локациях).

### 1.1 `stamina` (Личный ресурс протагониста)

- **Смысл:** Энергия, фокус и нервное напряжение лидера.
- **На что тратится:** Сложные социальные взаимодействия (убеждение, допрос), взлом, крафт, точечные исследования.
- **Восстановление:** Только при полноценном ночлеге (завершение дня / `onDayEnd`). Обычные привалы в пути личную стамину не восстанавливают, чтобы игрок не злоупотреблял отдыхом ради бесконечных диалогов.

### 1.2 `expeditionPoints` (Макро-ресурс отряда)

- **Смысл:** Готовность группы к маршу, способность тащить припасы и преодолевать препятствия.
- **На что тратится:** Переходы по глобальной карте (travel transitions), тяжелый физический труд отряда (например, разбор завалов).
- **Как вычисляется:** Это производный параметр, который высчитывается движком на лету по формуле, учитывающей синергию отряда.

**Формула `expeditionPoints`:**
`(Сумма стамины всех участников / Количество участников) * (1 + (0.1 * Количество спутников))`

_Почему это работает:_

- Слабый персонаж (например, ученый) ожидаемо тянет среднее арифметическое вниз — игрок ощущает, что гражданского приходится "тащить" на себе.
- Синергетический множитель `(1 + 0.1n)` компенсирует это падение в больших группах. Отряд из 4 человек эффективно распределяет лагерный быт, поэтому слабый спутник перестает быть критической обузой.
- Игрок мотивирован прокачивать физические характеристики любых спутников, так как это пассивно увеличивает дальность хода всей экспедиции.

### 1.3 Интеграция в ActionCost

В базе Экшенов это устраняет необходимость прописывать двойные стоимости. Структура `ActionCost` расширяется[cite: 7]:

```ts
export interface ActionCost {
  expeditionPoints?: ActionNumber; // Макро-ресурс отряда (переходы, тяжелый труд)
  stamina?: ActionNumber; // Личный ресурс протагониста (социалка, крафт)[cite: 7]
  time?: ActionNumber; // Затраты внутриигрового времени[cite: 7]
  money?: ActionNumber; // Деньги[cite: 7]
  items?: {
    itemId: ItemId;
    count: ActionNumber;
  }[]; // Требуемые предметы[cite: 7]
}
```

- Навигационные экшены требуют только `expeditionPoints`.
- Диалоговые и рабочие экшены требуют только `stamina`[cite: 7].
- Движку не требуется сложная синхронизация состояний спутников, а контент-мейкеру не нужно дублировать косты при написании initial-данных[cite: 7].

### 1.4 Уход в минус и статусы истощения (Fatigue Debuffs)

Чтобы предотвратить "софт-лок" (невозможность сдвинуться с места при 0 expeditionPoints), макро-ресурс отряда может уходить в отрицательные значения. Достижение нуля не блокирует навигационные экшены, но накладывает на группу штрафы, отражающие крайнюю степень изнеможения марш-броском.

Уровни усталости:

От 0 до -50 (Легкая усталость): Небольшие штрафы. Игрок понимает, что пора искать место для привала.

От -50 до -100 (Усталость): Заметное снижение всех боевых характеристик отряда. Усложнение проверок (checks) на глобальной карте.

Ниже -100 (Тяжелая усталость): Критические штрафы к характеристикам в бою. Шансы на успешные проверки минимальны. Высокий риск гибели при любом случайном столкновении (Encounter).

Почему это работает: Это создает мощный инструмент риск-менеджмента. Игрок сам принимает драматичные решения: остановиться в опасной зоне и потратить последнюю еду на привал, или «гнать отряд» до безопасной базы, надеясь, что по пути на них никто не нападет, так как в бою истощенная группа будет почти беспомощна.
