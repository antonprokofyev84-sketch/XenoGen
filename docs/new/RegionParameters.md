# Региональные параметры

Типы: [region.types.ts](../../src/types/region.types.ts).
Resolver: [regionLevels.ts](../../src/systems/world/regionLevels.ts).

## Смысл и шкала

Ниже — игровой смысл параметров и целевые применения в балансе. Фактически
реализованные общие операции — разрешение локальных уровней и дневные изменения
raw-значений; конкретное влияние на товары и encounters задаётся их системами.

| Параметр        | Смысл                                 | Основные применения                                   |
| --------------- | ------------------------------------- | ----------------------------------------------------- |
| `prosperity`    | Обилие товаров и насыщенность рынка   | Количество и редкость товаров, локальные цены         |
| `techLevel`     | Доступ к технологиям и инфраструктуре | Ассортимент, оружие, броня и медицина                 |
| `contamination` | Заражение и загрязнение               | Мутанты, средовые угрозы, спрос на защиту и лекарства |
| `threat`        | Опасность и опыт враждебных сил       | Сложность encounters, засады и качество противника    |

Клетка хранит полный набор raw-значений `0..999`, включая дробные. Игровые системы
потребляют целые уровни `0..9`: `floor(raw / 100)`.

Ориентиры: prosperity 0 — скудный рынок, 5 — устойчивый, 9 — изобилие;
techLevel 0 — простое снаряжение, 5 — развитое, 9 — экспериментальные технологии;
contamination 0 — чистая среда, 9 — тяжёлое заражение;
threat 0 — неопытные враги, 9 — профессионалы и опасные сценарии.

Параметры независимы. Высокий threat при низком techLevel описывает опытных бойцов
с простым оружием; низкий threat при высоком techLevel — слабую охрану развитой
инфраструктуры. Технологии создаются поселениями, фракциями и объектами, а не типом почвы.

Prosperity регулирует объём запасов, появление обычных товаров и повышение
редкости; само по себе богатство не делает врагов опытнее, но может означать
больше охраны и ценных целей. Tech level определяет доступный класс снаряжения,
включая импланты, медицину и генетические препараты.
Contamination также влияет на заражённые товары и спрос на фильтры, антидоты
и защиту. Threat описывает прежде всего качество бойцов и опасность сценариев,
а не просто количество врагов; спрос на боевые товары может учитывать его в ценах.

## Локальные уровни POI

Для каждого параметра `resolvePoiRegionLevels`:

1. Берёт уровень root cell.
2. При наличии `regionLevelOverrides` использует override, иначе прибавляет
   `regionLevelModifiers`.
3. Ограничивает итог диапазоном `0..9`.

Overrides — целые уровни, modifiers — целые дельты. Если параметр присутствует
в обеих maps, применяется override, а modifier этого параметра игнорируется.
Вложенный POI берёт основу из root cell; локальное изменение
родителя не наследуется. Разные параметры можно задать разными способами.

Например, рынок с techLevel 3 и modifier `+2` даёт уровень 5.
Override `7` даёт уровень 7 независимо от исходного уровня клетки.
Например, богатый квартал получает `prosperity: +2`, лаборатория — высокий
techLevel override и contamination modifier. Эти настройки меняют локальный
контекст POI, сохраняя исходные raw-параметры клетки. Потребители используют
единый resolver, чтобы торговля и encounters получали согласованные уровни.

## Изменение региона

`changeRegionParameter` меняет raw-параметр root cell владеющего POI. Его поля:
`cellParam`, дробная или целая `delta`, optional `chance`, `min`, `max`.
Defaults: chance 1, min 0, max 999.

`onDayPass` template содержит такие effects. Каждому эффекту проводится независимый
бросок каждый день; скрытые POI также участвуют в симуляции.
Границы влияния насыщают изменение, сохраняя уже вышедшее за границу значение:

| Исходное | Effect                | Результат |
| -------- | --------------------- | --------- |
| 398      | `delta: 5, max: 400`  | 400       |
| 500      | `delta: 5, max: 400`  | 500       |
| 2        | `delta: -5, min: 0`   | 0         |
| 100      | `delta: -5, min: 200` | 100       |

```ts
onDayPass: [
  { type: 'changeRegionParameter', cellParam: 'contamination', delta: 1, chance: 0.3, max: 400 },
];
```

Дневной порядок и удаление источников описаны в
[runtime](interaction-runtime-state-design.md#мировое-время-и-конец-дня) и
[жизненном цикле POI](poi-initial-data-design.md#жизненный-цикл).
