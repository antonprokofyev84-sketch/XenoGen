# POI UI — актуальный контракт

Сохранённый вариант с отдельной правой секцией портретов перенесён в игру
26 октября 2026. Эталон: `game-shell-saved-side-portraits.html` из прототипов
этого чата. Эксперимент с портретами в заголовке панели не принят.

## Композиция и общая оболочка

- Сцена 1600×900 CSS px без масштабирования, рамка 1 px. В большом окне
  центрируется, в меньшем прокручивается внешний viewport.
  Общий `GameScene` находится в `src/components/GameHud/`.
- Фон POI заполняет сцену. Фигура слева: полный холст высотой 1000 px,
  верх y=70, контейнер x=0 шириной 440 px, изображение центрировано внутри.
  Низ обрезается границей сцены, примерно на середине икр демонстрационного NPC.
  Контейнер с `overflow: hidden` не создаёт прокрутку самой сцены.
- Панель действий: x=440, bottom=24, 800×224 px. Положение и размер одинаковы
  в локации и разговоре. Две колонки, до шести Actions на странице;
  остальные доступны через Previous/Next в заголовке, порядок resolver сохраняется.
  Длинные подписи остаются целыми, при необходимости область прокручивается.
- В заголовке POI root нет повторного названия и Explore the area.
  NPC-контекст показывает имя и отличающуюся роль; внутренний Frame без NPC —
  своё название. History и Leave/End talk находятся справа.
  Системный выход доступен только там, где runtime предоставляет родительский
  переход либо возврат из NPC root. Внутренние Frames используют авторские Actions.
- Справа сверху общий `GameHud`: название, родитель, реальный статус доступа,
  время, очки экспедиции и четыре иконки региональных уровней (одна цифра 0..9).
  Уровни вычисляет канонический resolver, включая локальные modifiers/overrides.
  Данные непосещённой клетки неизвестны: «—», без раскрытия raw-значений.
  Exploration не показывается. Ширина блока 272 px, отступы top/right по 24 px.
- Верхний блок сворачивается до названия, дня, часов и очков. Флаг
  `ui.isLocationHudCollapsed` сохраняется при смене экрана и открытии инвентаря.
  Очки экспедиции пока «—»: демонстрационные 38 из прототипа не перенесены.
- Ниже HUD — прямой список доступных дочерних переходов, без dropdown.
  Заблокированный вход виден с причиной, pendingRemoval не предлагается.
  Во время чтения переходы disabled; обычная навигация существует только в root.
- Справа снизу `GameSystemMenu`: 272×96 px, bottom/right по 24 px,
  четыре квадратные кнопки 56×56 px в одном ряду. Иконки и подписи при
  наведении/фокусе. Inventory работает через существующий возврат на вызывающий
  экран. Map открывает существующую карту без завершения interaction; если
  партия внутри POI, карта работает только для просмотра: нет перемещения,
  разведки и отдыха, есть Return to location с сохранением reading/completion.
  Party/Settings пока сохраняют статус disabled-заглушек.
- Над меню портретная панель Available characters: 272×116 px, bottom=132.
  Вместе с промежутком 12 px и меню занимает 224 px, её верх и низ совпадают
  с панелью действий. Четыре карточки 56×76 px, портреты 56×56, подпись одной
  строкой с ellipsis и полным именем в tooltip. Пустые места — неинтерактивные рамки.
  При более чем четырёх occupants доступны страницы, NPC не теряются.
- Портреты сохраняются в разговоре и во внутренних Frames; текущий NPC подсвечен.
  Их список берётся из кешированного occupancy текущего POI, без повторного RNG.
  Выбор разрешён в root после чтения; во внутренних/forceExit Frames и во время
  narrative карточки disabled. Переход NPC → NPC использует существующий
  enterContext с регистрацией встречи и новым логом.
- Текст заменяет Actions в той же области. Продолжение кликом/пробелом после
  анимации; выделение текста, repeat keydown и двойной клик защищены.
  Второй клик одной последовательности не запускает появившийся Action;
  клавиатурная активация кнопок сохраняется без дополнительной задержки.
  История — модальное окно с затемнением, закрытием кнопкой/Escape/снаружи.

## Стиль и общие компоненты

`src/components/GameHud/_theme.scss` содержит единую палитру и панели,
`_button.scss` — кнопки на основе CSS пользователя. Иконки — `GameIcon.tsx`,
POI использует его через совместимый реэкспорт `PoiIcon`.

Панели: border 1 px, нативный `corner-shape: bevel`, полосатый полупрозрачный
фон, слабый внутренний контур и тёплое свечение. Кнопки действий/переходов/истории
используют общий `game-button`, высота от 44 px; системные — 56 px.
Без clip-path, SVG-рамок, blur и дополнительных декоративных слоёв.
`GameTooltip` использует Floating UI и portal с `poiTheme`; он общий для Actions,
навигации и HUD. `aria-describedby` назначается непосредственно дочернему
контролу, подсказка закрывается по Escape, показывается при наведении и фокусе.
Шрифты: заголовок 21 px, narrative 18 px, Actions 17 px, вторичный текст 14 px.

Карта использует ту же оболочку, HUD и меню. Существующие сетка клеток,
перемещение, разведка и отдых сохранены. Справа — обнаруженные POI выбранной
клетки с информацией при наведении/фокусе. Вымышленные маркеры, маршруты,
временные скорости и значения из HTML-макета не становятся игровыми механиками.

## Чтение и исполнение

`CurrentInteraction.reading` — union `actions` либо `narrative` с resolved blocks
и необязательным `ActionCompletion { transition?, time }`. История остаётся в `log`.
Порция текста формируется из записей одной операции, включая silent Interceptors
и открытый ими Frame. Текст не извлекается повторно из всей истории.

1. Начать Action можно только в режиме `actions`.
2. Один раз разрешить cost, списать деньги/предметы/личную stamina, учесть попытку.
3. Один раз выполнить check/weighted outcome, применить effects и записать narrative.
4. Если полный блок effects достиг порога tension, заменить authored queue системным
   `forceExit`. Это планирование, а не немедленное открытие его Frame.
5. При непустом narrative сохранить только transition и минуты и дождаться чтения.
   Без narrative завершить сразу, без пустого дополнительного клика.
6. `continueInteraction` сначала забирает completion, затем выполняет переход и время.
   Travel использует обычную мировую команду и суммирует путь с минутами Action.
7. После мировых последствий обработать pending events в root и подготовить варианты
   действительно видимого экрана. Новый текст снова открывает режим `narrative`.

Плата, effects и RNG при продолжении не повторяются. Смена/завершение контекста
удаляет его reading и completion. Локальный `root` не повторяет вступление, но
применяет background и продолжает очередь. Interceptors исполняют свои transitions
атомарно при входе; пауза относится к результатам выбранных игроком Actions.

`forceExit` — единственный системный item обычной `pendingEvents`, заменяющий её
authored-остаток. Он переживает refresh, ждёт root и не прерывает внутренние Frames.
При очистке помеченных POI в конце дня партия переносится к первому сохранившемуся
родителю. Пометка до конца дня не удаляет текущий POI немедленно.

## Авторские и производные данные

- Интерфейс POI и пользовательский текст initial-fixtures (названия, роли,
  narrative, Actions, Interceptors и квесты) используют английский язык.
  Это не вводит переключатель локали: `LocalizedText` пока остаётся строкой.
- Action имеет optional `category`: `dialogue | quest | trade | rest | interaction`.
  Default — `interaction`. Источник quest всегда получает звезду; внутри Frame
  категорию задаёт автор. Порядок frame/poi/slot/personal/quest сохраняется.
- `UiAction` содержит money preview, hints и причины disabled. Один resolved cost
  используется и для проверки, и для preview; executor разрешает стоимость попытки
  отдельно. Время и вероятность не показываются. Скрытые conditions не раскрываются.
- `InitialFrame.title?: LocalizedText` задаёт человекочитаемое название сцены.
- `none`: фигуры нет; `speaker`: последний NPC из текущего текста, только при чтении;
  `always`: контекстный NPC либо временно другой speaker. Всегда не более одной фигуры.
- Assets NPC: `src/assets/npcs/<npcId>/full-body.webp|png` и отдельный `portrait.webp|png`.
  Стандарт размеров, кадрирования и хранения описан в `visual-assets.md`.
  Имя незнакомого NPC выводится через единый resolver роли; встречи считаются на выходе.
- Рюкзак сохраняет вызывающий экран и возвращает к тому же interaction/reading.
  Он не завершает ожидающий Action и не пересчитывает уже выполненную проверку.
- Очки экспедиции — «—», без новой механики и демонстрационной стоимости у Actions.
- Отряд/настройки в системном меню пока disabled-заглушки.

## Проверки и границы

`readingFlow.test.ts` и `npcMeetings.test.ts` проверяют domain/orchestration:
однократность оплаты, check, effects и времени, возвраты, сохранение в рюкзаке,
forceExit, имена/speaker, preview, валидность данных и дневную очистку POI.
`actionSourceUniqueness.test.ts` проверяет повторные привязки root Actions:
Frame/template, Frame/slot, personal/quest и одновременные квесты. Разные стадии
одного квеста и внутренние Frames могут повторно использовать Action.
`locationPresentation.test.ts` дополнительно проверяет единый fallback названий
и отсутствие повторных Actions в root keeper/visitor.

Изменения UI не утверждают новые правила боя, торговли, сохранений или усталости.
Демонстрационная таверна использует технические fixtures, а не production-квест.
Версия от 26 октября проверена: production build, целевой ESLint и Prettier,
44 теста, git diff --check. В браузере проверены POI root, чтение, NPC,
страницы Actions, внутренний Frame, история, инвентарь, просмотр карты с
возвратом к непрочитанной реплике и общий HUD карты. Геометрия 800×224,
совпадение верхней/нижней границ правых блоков и отсутствие внутренней
прокрутки сцены подтверждены в 1600×900.
