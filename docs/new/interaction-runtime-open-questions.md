# Interaction Runtime: открытые вопросы

Этот документ фиксирует восемь оставшихся блоков вопросов по реализации `interaction runtime`.

## 1. Структура interaction state

- текущий `POI`, `slot` или NPC-контекст;
- `activeFrameId`;
- очередь `pendingInterceptorIds`;
- дневная память выполнений Actions и Interceptors;
- долговременные счётчики `executionLimit.total`;
- сохранённые результаты `appearanceChance`.

## 2. Сборка root-контента

- базовые Actions текущего POI;
- Actions текущего slot;
- персональные Actions NPC;
- квестовые runtime-индексы Actions и Interceptors;
- динамические переходы к slots и дочерним POI.

## 3. Исполнение Action

- единый `performAction`;
- порядок проверки `conditions`, `requirements`, execution limits и `cost`;
- разрешение динамических числовых значений;
- выполнение `check` и выбор соответствующего `ActionResult`;
- последовательное применение `Effect[]`;
- запись результата в interaction log;
- выполнение `transition`.

## 4. Работа Interceptors

- первоначальная сборка очереди при входе в контекст;
- повторная проверка `conditions` непосредственно перед выполнением каждого Interceptor;
- приостановка очереди, если Interceptor открыл Frame;
- пересборка очереди после смены time slot;
- ожидание root перед запуском следующего Interceptor;
- обработка смены контекста после обновления occupancy.

## 5. Переключение POI ↔ slot/NPC

- где хранится текущий контекст;
- сохраняется ли общий interaction log при переключении;
- какой runtime action открывает slot;
- как закрывать NPC-контекст, если NPC ушёл по расписанию.

## 6. Время и конец дня

- точную транзакционную границу Action, если его `cost` переводит игру в следующий time slot или день;
- порядок дневных тиков;
- обработку квестовых таймеров;
- очистку всей дневной памяти Actions и Interceptors;
- единое удаление POI, рекурсивно помеченных на удаление;
- пересчёт occupancy после завершения дневных изменений.

## 7. Внешние переходы

- запуск боя и возврат из него;
- открытие послебоевого Frame;
- приоритет `forceExit` относительно остальных переходов;
- переход непосредственно в другой POI;
- удаление текущего POI после выхода из него.

## 8. Interaction log

- срок жизни interaction log;
- состав presentation snapshots;
- нужно ли сохранять уже разрешённый фон Frame;
- нужно ли сохранять выбранный visual variant персонажа;
- нужно ли сохранять отображаемое имя speaker на момент добавления записи.
