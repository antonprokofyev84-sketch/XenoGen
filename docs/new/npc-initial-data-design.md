# NPC: данные, расписания и встречи

Формат: [npcContent.types.ts](../../src/types/npcContent.types.ts).
Реестр: `src/data/initial/npcs.ts`; размещение — `src/state/gameSlices/occupancy.ts`.

## Definition

NPC задаёт `name`, `gender`, `faction`, полный `baseSchedule`, optional `affection`,
`timesMet`, личные `actionIds` и `interceptorIds`. ID — ключ реестра.
`gender` принимает `male`/`female`. Для NPC вне сюжетных фракций используется
`independents`, чья репутация к игроку постоянна.
Пол выбирает fallback-изображение, но не задаёт физический рост.

Начальные `affection` и `timesMet` по умолчанию равны 0. Рабочий диапазон affection —
`-100..100` — балансный ориентир soft limits; текущее число сохраняется без clamp.
Идентичность хранится в initial definition; изменяемые отношение,
встречи и resolved schedule — в NPC runtime.
Положительный initial `timesMet` позволяет начать игру со знакомым NPC.
Характеристики для боя и вступления в партию проектируются отдельно от личности
NPC — [связь со stat templates](ideas.md#interaction-и-изображения).

Персональные Actions и Interceptors следуют за NPC независимо от роли.
Например, личную просьбу Боба можно обсудить и в таверне, и дома, а услуга
бармена относится к [slot таверны](poi-initial-data-design.md#npc-slots).

Пример обязательного полного расписания:

```ts
baseSchedule: {
  late_night: 'home',
  early_morning: 'hidden',
  morning: 'work',
  afternoon: 'work',
  evening: 'freeTime',
  night: 'home',
}
```

## Расписания и occupancy

`baseSchedule` явно описывает все шесть частей суток:

| Состояние  | Допустимое размещение                  |
| ---------- | -------------------------------------- |
| `work`     | Рабочий slot подходящего открытого POI |
| `freeTime` | Slot свободного времени                |
| `home`     | Домашний slot                          |
| `hidden`   | NPC скрыт                              |

Связи с работой, домом и местами отдыха задаются [slots POI](poi-initial-data-design.md#npc-slots).
Base schedule говорит когда, candidate pool или assignment — где.

Resolved schedule вычисляется глобально. Один NPC имеет не более одной работы;
runtime work assignment заменяет его статическую рабочую привязку. В рабочее время
NPC зарезервирован за work-группой даже до посещения места. При неподходящем или
закрытом workplace он остаётся неразмещённым.
Участие в static work candidate pool допустимо только для одного рабочего места.
Runtime work assignment переводит NPC на новую работу, заменяя static membership;
одновременно назначить его на две работы нельзя. `work` в schedule сам по себе
не создаёт рабочего места, а candidate pool не делает NPC работником вне часов `work`.

Actual occupancy создаётся лениво при первом посещении POI в time slot и кешируется.
Повторный вход использует тот же состав. Размещение идёт по группам
`work → freeTime → home`; NPC занимает максимум один slot.
Внутри группы slots обходятся по порядку массива: первый подходящий slot получает
NPC раньше следующих. После успешного chance roll кандидат случайно выбирается
среди совместимых со schedule и ещё свободных NPC.
Первый slot получает преимущество; дополнительного оптимального распределения нет.
Неудачный chance или недоступное рабочее место оставляют NPC неразмещённым,
сохраняя выбранную schedule-группу без перехода в `freeTime` или `home`.

Персональное назначение эксклюзивно: совместимый свободный NPC занимает slot
без chance roll. Если он недоступен, slot остаётся пустым. Автоматическое заполнение
использует candidate pool и chance; назначения этот pool не меняют.

## Встречи и отображаемое имя

`timesMet > 0` означает знакомство. При завершении разговора или смене текущего NPC
`registerNpcMeeting` увеличивает счётчик максимум раз за календарный день и обновляет
`lastDateMet`. Переходы между Frames одного разговора сохраняют встречу открытой.
Само присутствие NPC в occupancy встречей не считается.

До знакомства отображается роль текущего slot, после — имя NPC. У неразмещённого
NPC отображается имя. Narrative snapshots
фиксируют отображаемые значения до показа, поэтому старый текст сохраняет смысл.
Индивидуальные картинки и выбор fallback — [стандарт изображений](visual-assets.md).
